OptimalControlProblems.Problem — Type
struct Problem{M, I<:NamedTuple}

An optimal control problem of the collection: the continuous model, as written with OptimalControl, and its initial guess. Discretizing and solving it is left to OptimalControl.solve, where the scheme, the grid, the modeler and the solver are chosen.

A Problem is returned by a problem function for the OptimalControl modelings. Read it through model(pb), initial_guess and metadata(pb).

Fields

  • name::Symbol: Name of the problem.

  • modeling::Symbol: Modeling the problem is written in, e.g. :OptimalControl.

  • ocp::Any: Continuous optimal control problem.

  • init::NamedTuple: Initial guess, a NamedTuple (state=…, control=…, variable=…).

  • metadata::OrderedCollections.OrderedDict{Symbol, Any}: Metadata of the problem, with the parameters this instance was built with.

Example

julia> using OptimalControl, OptimalControlProblems
julia> pb = beam(OptimalControlBackend())
julia> sol = solve(model(pb); init=initial_guess(pb), grid_size=500)

OptimalControlProblems.problem_metadata — Method
problem_metadata(
    problem::Symbol
) -> OrderedCollections.OrderedDict

Return a dictionary containing the metadata of problem, without building it.

The metadata of a built problem is read with metadata(pb) on the Problem. The following keys are valid:

  • grid_size::Int: the default number of steps. For example:
:grid_size => 500,
  • parameters::Union{Nothing,NamedTuple}: the list of parameters. For example:
:parameters => (
    t0 = 0,
    tf = 1,
    x₁_l = 0,
    x₁_u = 0.1,
    x₁_t0 = 0,
    x₂_t0 = 1,
    x₁_tf = 0,
    x₂_tf = -1,
),
  • status: the status (:valid or :draft) of the problem in each modeling.

Example

julia> data = problem_metadata(:beam)
julia> data[:grid_size]
500

OptimalControlProblems.problems — Method
problems(; status) -> Vector{Symbol}

Returns the sorted list of optimal control problems.

Availability comes from the model files present in ext/<modeling>Models/; the status (:valid or :draft) of each problem in each modeling comes from its metadata.

  • problems(): problems having the requested status in at least one modeling.
  • problems(backend): problems available in that modeling with the requested status.
  • problems(backend1, backend2, ...): problems available in all the given modelings with the requested status, which is the list to use to compare modelings.

Keyword arguments

  • status::Symbol=:valid: :valid, :draft or :all.

Returns

  • Vector{Symbol}: A vector of problem names as symbols.

Example

julia> OptimalControlProblems.problems(JuMPBackend(), OptimalControlBackend())
[:balanced_field, :beam, ...]

OptimalControlProblems.solution — Function
solution(model, pb::Problem) -> CTModels.Solution

Build the CTModels.Solution of a solved model of the same problem as pb, to show and plot it as an OptimalControl solution: state(sol), control(sol), costate(sol), objective(sol), iterations(sol) and plot(sol) work on it, and model(sol) === model(pb).

The method for a JuMP model (trapezoidal scheme) is defined by the JuMPModels extension: load JuMP. The model and pb must have the same state, control and variable dimensions.

OptimalControlProblems.solution — Method
solution(
    model::GenericModel,
    pb::Problem
) -> CTModels.Solutions.Solution{TimeGridModelType, TimesModelType, StateModelType, ControlModelType, VariableModelType, ModelType, CostateModelType, Float64, CTModels.Solutions.EmptyDualModel, CTModels.Solutions.SolverInfos{Any, Dict{Symbol, Any}}} where {TimeGridModelType<:CTModels.Solutions.AbstractTimeGridModel, TimesModelType<:CTModels.Components.AbstractTimesModel, StateModelType<:CTModels.Components.AbstractStateModel, ControlModelType<:CTModels.Components.AbstractControlModel, VariableModelType<:CTModels.Components.AbstractVariableModel, ModelType<:CTModels.Models.AbstractModel, CostateModelType<:Function}

Build the CTModels.Solution of a solved JuMP model, from the continuous model of pb, the Problem of the same problem in OptimalControl. The states and the controls are given at the nodes of the grid of the model (trapezoidal scheme) and the controls are interpolated linearly; the costate is given on the intervals of the grid. The costate keeps the convention of the JuMP model: its signs are not yet those of OptimalControl (#326).

Arguments

  • model::JuMP.GenericModel: A solved JuMP model of the collection.
  • pb::OptimalControlProblems.Problem: The problem of the same name, for the OptimalControl modelings.

Throws

  • CTBase.Exceptions.PreconditionError: If the model has not been solved.
  • CTBase.Exceptions.IncorrectArgument: If the dimensions of the model and of pb differ.

Example

julia> using JuMP, Ipopt, OptimalControl, OptimalControlProblems
julia> model = beam(JuMPBackend(); grid_size=100)
julia> set_optimizer(model, Ipopt.Optimizer); optimize!(model)
julia> sol = solution(model, beam(OptimalControlBackend()))
julia> plot(sol)
