On this page

Developers ​

How the collection is built, tested and documented. The procedures live next to the code they describe, in READMEs, so that they change with it; this page says where to find them.

The principle ​

What can be computed is generated or checked, never maintained by hand. The availability of a problem in a modeling is the presence of its file; the features are computed from the model; the reference objectives from the results of the crons; the documentation pages from the files of each problem. A test checks that no list of problems is written by hand.

Three kinds of tests ​

KindWhenFails on
Does not breakevery pull request, small grid, a few iterationsan exception or a non-finite objective
Same NLPevery pull request, no solvetwo modelings that give different NLPs
Convergencethe weekly crons, or on demand (label test convergence)nothing: the solver status and the gap to the reference are reported

The convergence results feed the reference objectives and the problem pages, and the Status page shows the latest reports.

The documentation ​

The problem pages, the Status page and the API Reference are generated at each build; docs/modelings.jl holds what the pages need to know about each modeling. The build solves nothing for the problem pages: their results come from the crons. To build it locally:

bash
julia --project=docs docs/make.jl
npx serve docs/build/1 --listen 5173
