The Goddard rocket problem is a classical optimal control problem that models the ascent of a vertically launched rocket. The objective is to maximise the final altitude by optimally controlling the thrust, while accounting for atmospheric drag, gravity, and fuel consumption. This problem is notable for its inclusion of singular arcs, where the control is neither at its maximum nor minimum, complicating the solution process. Historically, it was first proposed by Robert H. Goddard in 1919 (A Method of Reaching Extreme Altitudes), one of the founding works in modern rocketry.

Qualitative behaviour ​

The optimal trajectory often exhibits a bang–singular–bang structure, with thrust at maximum, then along a singular arc, and finally at minimum. The singular arc arises from the interplay of drag and gravity, producing a non-trivial optimal control law. This behaviour illustrates the complexity of the problem and the challenges in numerically resolving singular arcs.

Characteristics ​

  • Nonlinear coupled dynamics with drag and gravity,

  • Singular arcs in the optimal control,

  • State and control constraints,

  • Classical benchmark for testing optimal control algorithms, especially in aerospace applications.

References ​

  • Goddard, R. H. (1919). A Method of Reaching Extreme Altitudes. Smithsonian Institution, Washington D.C. The original formulation of the vertical rocket ascent problem, introducing fuel consumption, gravity, and drag effects.

  • Bryson, A. E. (1999). Dynamic Optimization. Addison Wesley Longman. pp. 392–394. Provides an introduction to singular arcs in optimal control with the Goddard rocket as a primary example.

  • Garfinkel, B. (1963). A Solution of the Goddard Problem. SIAM Journal on Control, 1(1), 1–20. doi:10.1137/0301020 Analytical and numerical solutions of the Goddard problem highlighting singular arc structures.

  • Tsiotras, P., & Kelley, H. J. (1992). Goddard Problem with Constrained Time of Flight. Journal of Guidance, Control, and Dynamics, 15(2), 394–399. doi:10.2514/3.20836 Study of time-constrained versions of the Goddard problem and associated optimal control strategies.

  • Bonnans, F., Martinon, P., & Trélat, E. (2007). Singular Arcs in the Generalized Goddard's Problem. arXiv:math/0703911 Analysis of singular arcs and numerical methods for the Goddard problem.

OptimalControl ​

valid

The continuous problem, written with the @def syntax of OptimalControl.jl, discretized and solved by OptimalControl.solve. Load OptimalControl and NLPModelsIpopt.

Get and solve ​

julia
using OptimalControl, OptimalControlProblems
using NLPModelsIpopt

pb = rocket(OptimalControlBackend())
sol = solve(
    model(pb), :collocation, :adnlp, :ipopt;
    init=initial_guess(pb),
    grid_size=500,
    scheme=:trapeze,
)
objective(sol)

The model ​

The model as written in ext/OptimalControlModels/rocket.jl, where the parameters are read from the metadata.

julia
ocp = @def begin
    tf ∈ R, variable
    t ∈ [t0, tf], time
    x = (h, v, m) ∈ R³, state
    T ∈ R, control

    # state constraints
    h(t) ≥ h_t0, (h_c)
    v(t) ≥ v_t0, (v_c)
    m_tf ≤ m(t) ≤ m_t0, (m_c)

    # control constraints
    T_l ≤ T(t) ≤ Tmax, (T_c)

    # time constraints
    tf ≥ tf_l, (tf_c)

    # initial conditions
    h(t0) == h_t0, (h_t0)
    v(t0) == v_t0, (v_t0)
    m(t0) == m_t0, (m_t0)

    # final conditions
    m(tf) == m_tf, (m_tf)

    # dynamics
    ẋ(t) == dynamics(h(t), v(t), m(t), T(t))

    # objective
    -h(tf) → min
end

OptimalControl, scalarized ​

valid

The same continuous problem, written with scalar components only, as needed by the ExaModels modeler on CPU and GPU. Load OptimalControl and MadNLP.

Get and solve ​

julia
using OptimalControl, OptimalControlProblems
using MadNLP

pb = rocket(OptimalControlScalarizedBackend())
sol = solve(
    model(pb), :collocation, :exa, :madnlp;
    init=initial_guess(pb),
    grid_size=500,
    scheme=:trapeze,
)
objective(sol)

The model ​

The model as written in ext/OptimalControlScalarizedModels/rocket.jl, where the parameters are read from the metadata.

julia
ocp = @def begin
    tf ∈ R, variable
    t ∈ [t0, tf], time
    x = (h, v, m) ∈ R³, state
    T ∈ R, control

    # state constraints
    h(t) ≥ h_t0, (h_c)
    v(t) ≥ v_t0, (v_c)
    m_tf ≤ m(t) ≤ m_t0, (m_c)

    # control constraints
    T_l ≤ T(t) ≤ Tmax, (T_c)

    # time constraints
    tf ≥ tf_l, (tf_c)

    # initial conditions
    h(t0) == h_t0, (h_t0)
    v(t0) == v_t0, (v_t0)
    m(t0) == m_t0, (m_t0)

    # final conditions
    m(tf) == m_tf, (m_tf)

    # dynamics
    D = (Dc * v(t)^2 * exp(-hc * (h(t) - h_t0)) / h_t0)
    g = g0 * (h_t0 / h(t))^2
    ∂(h)(t) == v(t)
    ∂(v)(t) == (T(t) - D - m(t) * g) / m(t)
    ∂(m)(t) == -T(t) / c

    # objective
    -h(tf) → min
end

JuMP ​

valid

A JuMP model, already discretized: the scheme and the grid are chosen when the problem is built. Load JuMP and Ipopt.

Get and solve ​

julia
using JuMP, Ipopt, OptimalControlProblems

nlp = rocket(
    JuMPBackend();
    grid_size=500,
    scheme=:trapeze,
)
set_optimizer(nlp, Ipopt.Optimizer)
optimize!(nlp)
objective_value(nlp)

The model ​

The model as written in ext/JuMPModels/rocket.jl, where the parameters are read from the metadata.

julia
data = ProblemData(;
    state=[
        Component("h"; lower=h_t0),
        Component("v"; lower=v_t0),
        Component("m"; lower=m_tf, upper=m_t0),
    ],
    control=[Component("T"; lower=T_l, upper=Tmax)],
    variable=[Component("tf"; lower=tf_l)],
    costate=["∂h", "∂v", "∂m"],
    times=v -> (t0, v[1]),
    dynamics=(x, u, v, t) -> dynamics(x, u),
    cost=(I, x0, xf, v) -> -xf[1],
    boundary=[
        (h_t0, (x0, xf, v) -> x0[1], h_t0),
        (v_t0, (x0, xf, v) -> x0[2], v_t0),
        (m_t0, (x0, xf, v) -> x0[3], m_t0),
        (m_tf, (x0, xf, v) -> xf[3], m_tf),
    ],
)

Comparison of the modelings ​

Same problem ​

Two modelings of the same problem, discretized the same way, must give the same nonlinear program: same variables, constraints, objective and derivatives at the initial guess. This is what is compared, not the solutions: two solves are two optimization paths.

  • OptimalControl, scalarized and OptimalControl: same NLP, checked on every pull request.

  • JuMP and OptimalControl: same NLP, checked on every pull request.
