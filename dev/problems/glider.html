The hang glider problem is a classical benchmark in optimal control. It consists of steering a hang glider from an initial horizontal position and altitude to a target altitude while maximising the horizontal distance travelled. The glider dynamics incorporate lift, drag, gravity, and the effect of a thermal updraft. The control variable is the lift coefficient , which modulates the aerodynamic lift and influences the trajectory through the thermal region.

Qualitative behaviour ​

  • The optimal trajectory exploits the thermal updraft to maximise horizontal distance.

  • The lift coefficient balances altitude loss and horizontal progression.

  • The dynamics are nonlinear due to the coupling of lift, drag, and relative velocity in the thermal.

  • Horizontal velocity is maintained positive, and the trajectory respects the control and state constraints.

Characteristics ​

  • Nonlinear four-dimensional dynamics with one control input.

  • Free final time.

  • Mixed state and control constraints.

  • Widely used as a benchmark for trajectory optimisation and direct transcription methods in nonlinear optimal control.

  • PSOPT GitHub Repository: Hang Glider Example. github.com/PSOPT/psopt/blob/master/examples/glider/glider.cxx Source code example for testing direct transcription and NLP solvers with the hang glider problem.

OptimalControl ​

valid

The continuous problem, written with the @def syntax of OptimalControl.jl, discretized and solved by OptimalControl.solve. Load OptimalControl and NLPModelsIpopt.

Get and solve ​

julia
using OptimalControl, OptimalControlProblems
using NLPModelsIpopt

pb = glider(OptimalControlBackend())
sol = solve(
    model(pb), :collocation, :adnlp, :ipopt;
    init=initial_guess(pb),
    grid_size=500,
    scheme=:trapeze,
)
objective(sol)

The model ​

The model as written in ext/OptimalControlModels/glider.jl, where the parameters are read from the metadata.

julia
ocp = @def begin
    tf ∈ R, variable
    t ∈ [t0, tf], time
    z = (x, y, vx, vy) ∈ R⁴, state
    cL ∈ R, control

    # state constraints
    x(t) ≥ x_l, (x_c)
    vx(t) ≥ vx_l, (vx_c)

    # control constraints
    cL_min ≤ cL(t) ≤ cL_max, (cL_c)

    # initial conditions
    x(t0) == x_t0, (x0_t0)
    y(t0) == y_t0, (y0_t0)
    vx(t0) == vx_t0, (vx0_t0)
    vy(t0) == vy_t0, (vy0_t0)

    # final conditions
    tf ≥ tf_l
    y(tf) == y_tf, (yf_tf)
    vx(tf) == vx_tf, (vxf_tf)
    vy(tf) == vy_tf, (vyf_tf)

    # dynamics
    ż(t) == dynamics(x(t), vx(t), vy(t), cL(t))

    # objective
    -x(tf) → min
end

OptimalControl, scalarized ​

valid

The same continuous problem, written with scalar components only, as needed by the ExaModels modeler on CPU and GPU. Load OptimalControl and MadNLP.

Get and solve ​

julia
using OptimalControl, OptimalControlProblems
using MadNLP

pb = glider(OptimalControlScalarizedBackend())
sol = solve(
    model(pb), :collocation, :exa, :madnlp;
    init=initial_guess(pb),
    grid_size=500,
    scheme=:trapeze,
)
objective(sol)

The model ​

The model as written in ext/OptimalControlScalarizedModels/glider.jl, where the parameters are read from the metadata.

julia
ocp = @def begin
    tf ∈ R, variable
    t ∈ [t0, tf], time
    z = (x, y, vx, vy) ∈ R⁴, state
    cL ∈ R, control

    # state constraints
    x(t) ≥ x_l, (x_c)
    vx(t) ≥ vx_l, (vx_c)

    # control constraints
    cL_min ≤ cL(t) ≤ cL_max, (cL_c)

    # initial conditions
    x(t0) == x_t0, (x0_t0)
    y(t0) == y_t0, (y0_t0)
    vx(t0) == vx_t0, (vx0_t0)
    vy(t0) == vy_t0, (vy0_t0)

    # final conditions
    tf ≥ tf_l
    y(tf) == y_tf, (yf_tf)
    vx(tf) == vx_tf, (vxf_tf)
    vy(tf) == vy_tf, (vyf_tf)

    # dynamics
    r = (x(t) / r_t0 - 2.5)^2
    UpD = u_c * (1 - r) * exp(-r)
    w = vy(t) - UpD
    v = √(vx(t)^2 + w^2)
    D = 0.5 * (c0 + c1 * (cL(t)^2)) * ρ * S * (v^2)
    L = 0.5 * cL(t) * ρ * S * (v^2)

    ∂(x)(t) == vx(t)
    ∂(y)(t) == vy(t)
    ∂(vx)(t) == -(L * w + D * vx(t)) / (m * v)
    ∂(vy)(t) == (L * vx(t) - D * w) / (m * v) - g

    # objective
    -x(tf) → min
end

JuMP ​

valid

A JuMP model, already discretized: the scheme and the grid are chosen when the problem is built. Load JuMP and Ipopt.

Get and solve ​

julia
using JuMP, Ipopt, OptimalControlProblems

nlp = glider(
    JuMPBackend();
    grid_size=500,
    scheme=:trapeze,
)
set_optimizer(nlp, Ipopt.Optimizer)
optimize!(nlp)
objective_value(nlp)

The model ​

The model as written in ext/JuMPModels/glider.jl, where the parameters are read from the metadata.

julia
data = ProblemData(;
    state=[
        Component("x"; lower=x_l),
        Component("y"),
        Component("vx"; lower=vx_l),
        Component("vy"),
    ],
    control=[Component("cL"; lower=cL_min, upper=cL_max)],
    variable=[Component("tf"; lower=tf_l)],
    costate=["∂x", "∂y", "∂vx", "∂vy"],
    times=v -> (t0, v[1]),
    dynamics=(x, u, v, t) -> dynamics(x, u),
    cost=(I, x0, xf, v) -> -xf[1],
    boundary=[
        (x_t0, (x0, xf, v) -> x0[1], x_t0),
        (y_t0, (x0, xf, v) -> x0[2], y_t0),
        (vx_t0, (x0, xf, v) -> x0[3], vx_t0),
        (vy_t0, (x0, xf, v) -> x0[4], vy_t0),
        (y_tf, (x0, xf, v) -> xf[2], y_tf),
        (vx_tf, (x0, xf, v) -> xf[3], vx_tf),
        (vy_tf, (x0, xf, v) -> xf[4], vy_tf),
    ],
)

Comparison of the modelings ​

Same problem ​

Two modelings of the same problem, discretized the same way, must give the same nonlinear program: same variables, constraints, objective and derivatives at the initial guess. This is what is compared, not the solutions: two solves are two optimization paths.

  • OptimalControl, scalarized and OptimalControl: same NLP, checked on every pull request.

  • JuMP and OptimalControl: same NLP, checked on every pull request.
