The Brachistochrone problem is a classical benchmark in the history of calculus of variations and optimal control.   It seeks the shape of a curve (or wire) connecting two points and within a vertical plane, such that a bead sliding frictionlessly under the influence of uniform gravity travels from to in the shortest possible time.   Originating from the challenge posed by Johann Bernoulli in 1696 Bernoulli 1696, it marks the birth of modern optimal control theory.   The problem involves nonlinear dynamics where the state includes position and velocity, and the control is the path's angle, with the final time being a decision variable to be minimised.

Qualitative behaviour ​

This problem is a classic example of minimum time control with nonlinear dynamics.   Unlike the shortest path problem (a straight line), the optimal trajectory balances the need to minimize path length with the need to maximize velocity.

The analytical solution to this problem is a cycloid—the curve traced by a point on the rim of a circular wheel as the wheel rolls along a straight line without slipping.   Specifically:

  • Energy Conservation: Since the system is conservative and frictionless, the speed at any height is given by   (assuming start from rest). This implies that maximizing vertical drop early in the trajectory increases velocity for the remainder of the path.

  • Concavity: The optimal curve is concave up. It starts steeply (vertical tangent if  ) to gain speed quickly, then flattens out near the bottom before potentially rising again to reach the target.

  • Singularity: At the initial point, if  , the control is theoretically singular as the bead has no velocity to direct. Numerical solvers often require a small non-zero initial velocity or a robust initial guess to handle this start.

The control is continuous and varies smoothly to trace the cycloidal arc.

Characteristics ​

  • Nonlinear dynamics involving trigonometric functions of the control.

  • Free final time problem (time-optimal).

  • Analytical solution is a Cycloid.

  • Historically significant as the first problem solved using techniques that evolved into the Calculus of Variations.

OptimalControl ​

valid

The continuous problem, written with the @def syntax of OptimalControl.jl, discretized and solved by OptimalControl.solve. Load OptimalControl and NLPModelsIpopt.

Get and solve ​

julia
using OptimalControl, OptimalControlProblems
using NLPModelsIpopt

pb = brachistochrone(OptimalControlBackend())
sol = solve(
    model(pb), :collocation, :adnlp, :ipopt;
    init=initial_guess(pb),
    grid_size=500,
    scheme=:trapeze,
)
objective(sol)

The model ​

The model as written in ext/OptimalControlModels/brachistochrone.jl, where the parameters are read from the metadata.

julia
ocp = @def begin
    tf ∈ R, variable
    t ∈ [t0, tf], time

    z = (px, py, v) ∈ R³, state
    u ∈ R, control

    -1.57 ≤ u(t) ≤ 1.57
    0.1 ≤ tf ≤ 20.0

    px(t0) == x0
    py(t0) == y0
    v(t0) == v0

    px(tf) == xf
    py(tf) == yf

    ∂(px)(t) == v(t) * sin(u(t))
    ∂(py)(t) == -v(t) * cos(u(t))
    ∂(v)(t) == g * cos(u(t))

    # Objectif
    tf → min
end

JuMP ​

valid

A JuMP model, already discretized: the scheme and the grid are chosen when the problem is built. Load JuMP and Ipopt.

Get and solve ​

julia
using JuMP, Ipopt, OptimalControlProblems

nlp = brachistochrone(
    JuMPBackend();
    grid_size=500,
    scheme=:trapeze,
)
set_optimizer(nlp, Ipopt.Optimizer)
optimize!(nlp)
objective_value(nlp)

The model ​

The model as written in ext/JuMPModels/brachistochrone.jl, where the parameters are read from the metadata.

julia
data = ProblemData(;
    state=[
        Component("px"),
        Component("py"),
        Component("v"),
    ],
    control=[Component("u"; lower=-1.57, upper=1.57)],
    variable=[Component("tf"; lower=0.1, upper=20.0)],
    costate=["∂px", "∂py", "∂v"],
    times=v -> (t0, v[1]),
    # Dymos formulation
    dynamics=(x, u, v, t) -> [x[3] * sin(u[1]), -x[3] * cos(u[1]), g * cos(u[1])],
    cost=(I, s0, sf, v) -> v[1],
    boundary=[
        (x0, (s0, sf, v) -> s0[1], x0),
        (y0, (s0, sf, v) -> s0[2], y0),
        (v0, (s0, sf, v) -> s0[3], v0),
        (xf, (s0, sf, v) -> sf[1], xf),
        (yf, (s0, sf, v) -> sf[2], yf),
    ],
)

Comparison of the modelings ​

Same problem ​

Two modelings of the same problem, discretized the same way, must give the same nonlinear program: same variables, constraints, objective and derivatives at the initial guess. This is what is compared, not the solutions: two solves are two optimization paths.

  • OptimalControl, scalarized and OptimalControl: same NLP, checked on every pull request.
