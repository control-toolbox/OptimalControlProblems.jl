Double oscillator ​

  • 4 state
  • 1 control
  • Lagrange cost
  • fixed final time
  • 1 control box
  • 2 boundary
  • OptimalControl valid
  • OptimalControl, scalarized valid
  • JuMP valid

The Double Oscillator problem is a benchmark in constrained optimal control illustrating the control of coupled mechanical systems with damping and stiffness effects. It consists of two masses connected by springs and a damper, with one mass directly influenced by an external periodic force and the other influenced indirectly through the coupling and a controlled damping term. Both the state trajectory   and the control   are decision variables. The aim is to minimise a quadratic cost that balances state deviations and control effort, subject to input constraints and the system dynamics.

Qualitative behaviour ​

  • The system exhibits coupled oscillatory dynamics due to interaction between the two masses through springs and damper.

  • The control input modulates the damping of the second mass, affecting the amplitude and phase of oscillations.

  • The quadratic cost penalises both deviations of the masses and the control effort, balancing tracking and energy usage.

  • Optimal trajectories often exhibit bang–bang behaviour on , consistent with theoretical results for mechanical oscillators under bounded control.

Characteristics ​

  • Coupled linear–nonlinear dynamics with external periodic forcing.

  • Control input enters through a damping term, introducing nonlinearity in the system response.

  • Bounded control with symmetric limits.

  • Widely used to benchmark numerical methods for constrained optimal control in mechanical systems.

  • Serves as a testbed for averaging methods and bang–bang control design.

OptimalControl ​

valid

The continuous problem, written with the @def syntax of OptimalControl.jl, discretized and solved by OptimalControl.solve. Load OptimalControl and NLPModelsIpopt.

Get and solve ​

julia
using OptimalControl, OptimalControlProblems
using NLPModelsIpopt

pb = double_oscillator(OptimalControlBackend())
sol = solve(
    model(pb), :collocation, :adnlp, :ipopt;
    init=initial_guess(pb),
    grid_size=500,
    scheme=:trapeze,
)
objective(sol)

The model ​

The model as written in ext/OptimalControlModels/double_oscillator.jl, where the parameters are read from the metadata.

julia
ocp = @def begin
    t ∈ [t0, tf], time
    x ∈ R⁴, state
    u ∈ R, control

    u_l ≤ u(t) ≤ u_u, (u_c)
    x₁(t0) == x₁_t0, (x₁_t0)
    x₂(t0) == x₂_t0, (x₂_t0)

    ẋ(t) == dynamics(x(t), u(t), F(t))

    0.5 * ∫(x₁(t)^2 + x₂(t)^2 + u(t)^2) → min
end

OptimalControl, scalarized ​

valid

The same continuous problem, written with scalar components only, as needed by the ExaModels modeler on CPU and GPU. Load OptimalControl and MadNLP.

Get and solve ​

julia
using OptimalControl, OptimalControlProblems
using MadNLP

pb = double_oscillator(OptimalControlScalarizedBackend())
sol = solve(
    model(pb), :collocation, :exa, :madnlp;
    init=initial_guess(pb),
    grid_size=500,
    scheme=:trapeze,
)
objective(sol)

The model ​

The model as written in ext/OptimalControlScalarizedModels/double_oscillator.jl, where the parameters are read from the metadata.

julia
ocp = @def begin
    t ∈ [t0, tf], time
    x ∈ R⁴, state
    u ∈ R, control

    u_l ≤ u(t) ≤ u_u, (u_c)
    x₁(t0) == x₁_t0, (x₁_t0)
    x₂(t0) == x₂_t0, (x₂_t0)

    F = sin((t - t0) * 2π / (tf - t0))
    ∂(x₁)(t) == x₃(t)
    ∂(x₂)(t) == x₄(t)
    ∂(x₃)(t) == -(k1 + k2) / m1 * x₁(t) + k2 / m1 * x₂(t) + 1 / m1 * F
    ∂(x₄)(t) == k2 / m2 * x₁(t) - k2 / m2 * x₂(t) - c * (1 - u(t)) / m2 * x₄(t)

    0.5 * ∫(x₁(t)^2 + x₂(t)^2 + u(t)^2) → min
end

JuMP ​

valid

A JuMP model, already discretized: the scheme and the grid are chosen when the problem is built. Load JuMP and Ipopt.

Get and solve ​

julia
using JuMP, Ipopt, OptimalControlProblems

nlp = double_oscillator(
    JuMPBackend();
    grid_size=500,
    scheme=:trapeze,
)
set_optimizer(nlp, Ipopt.Optimizer)
optimize!(nlp)
objective_value(nlp)

The model ​

The model as written in ext/JuMPModels/double_oscillator.jl, where the parameters are read from the metadata.

julia
data = ProblemData(;
    state=[Component("x$(c)") for c in "₁₂₃₄"],
    control=[Component("u"; lower=u_l, upper=u_u)],
    costate=["∂x₁", "∂x₂", "∂x₃", "∂x₄"],
    times=v -> (t0, tf),
    dynamics=(x, u, v, t) -> dynamics(x, u, t),
    lagrange=(x, u, v, t) -> 0.5 * (x[1]^2 + x[2]^2 + u[1]^2),
    boundary=[
        (x₁_t0, (x0, xf, v) -> x0[1], x₁_t0), (x₂_t0, (x0, xf, v) -> x0[2], x₂_t0)
    ],
)

Comparison of the modelings ​

Same problem ​

Two modelings of the same problem, discretized the same way, must give the same nonlinear program: same variables, constraints, objective and derivatives at the initial guess. This is what is compared, not the solutions: two solves are two optimization paths.

  • OptimalControl, scalarized and OptimalControl: same NLP, checked on every pull request.

  • JuMP and OptimalControl: same NLP, checked on every pull request.
