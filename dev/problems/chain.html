Chain ​

  • 3 state
  • 1 control
  • Mayer cost
  • fixed final time
  • 5 boundary
  • OptimalControl valid
  • OptimalControl, scalarized valid
  • JuMP valid

The Hanging Chain problem is a classical benchmark in optimal control. It consists of moving a chain from a given initial horizontal position to a target horizontal position while controlling the horizontal velocity of the chain. The objective is to reach the final configuration in a way that minimises the vertical displacement of the chain. This problem is widely used to test trajectory optimisation and direct transcription methods for nonlinear optimal control.

Qualitative behaviour ​

The optimal control trajectory exploits the nonlinear coupling between horizontal and vertical motion:

  • The state directly follows the control input (horizontal velocity).

  • The state evolves depending on , which introduces nonlinear dynamics in the vertical motion.

  • The state measures the chain extension and grows with the magnitude of .

The control typically balances horizontal movement to minimise the vertical displacement at the final time.

Characteristics ​

  • Nonlinear dynamics with three states and one control.

  • Minimum vertical displacement objective with boundary constraints.

  • Serves as a benchmark for trajectory optimisation and direct transcription methods in nonlinear optimal control.

References ​

  • More, J. J., & Munson, T. S. (2000). The Hanging Chain Problem as an Optimal Control Problem. mcs.anl.gov/~more/cops/bcops/chain.html This benchmark explicitly formulates the Hanging Chain (catenary) as an optimal control problem, including direct transcription to an NLP. It is widely used as a test case for solver performance in AMPL, MINOS, and other tools.

  • Dolan, E. D., & More, J. J. (2001). Benchmarking Optimisation Software with COPS 3.0. Technical Report ANL/MCS-TM-246, Argonne National Laboratory. mcs.anl.gov/~more/cops The COPS benchmark collection officially includes the Hanging Chain problem as one of its core examples. It provides comprehensive problem formulation, discretisation strategies, and solver comparison results.

  • Rutquist, P. E., & Edvall, M. M. (2009). Hanging Chain problem example in PROPT MATLAB Optimal Control Software. Included in the PSOPT distribution’s example suite, as credited by PSOPT’s list of examples (psopt.net). This demonstrates a practical implementation of the Hanging Chain problem via direct transcription using MATLAB-based optimal control software.

  • Huygens, C. (1690). Horologium Oscillatorium. Paris: F. Muguet. This foundational work contains one of the earliest studies of the hanging chain (catenary) curve. Huygens, along with Leibniz and Johann Bernoulli, contributed to the historical derivation of the catenary equation, which underlies modern optimal control formulations of the problem.

OptimalControl ​

valid

The continuous problem, written with the @def syntax of OptimalControl.jl, discretized and solved by OptimalControl.solve. Load OptimalControl and NLPModelsIpopt.

Get and solve ​

julia
using OptimalControl, OptimalControlProblems
using NLPModelsIpopt

pb = chain(OptimalControlBackend())
sol = solve(
    model(pb), :collocation, :adnlp, :ipopt;
    init=initial_guess(pb),
    grid_size=500,
    scheme=:trapeze,
)
objective(sol)

The model ​

The model as written in ext/OptimalControlModels/chain.jl, where the parameters are read from the metadata.

julia
ocp = @def begin
    t ∈ [t0, tf], time
    x ∈ R³, state
    u ∈ R, control

    # initial conditions
    x₁(t0) == x₁_t0, (x₁_t0)
    x₂(t0) == x₂_t0, (x₂_t0)
    x₃(t0) == x₃_t0, (x₃_t0)

    # final conditions
    x₁(tf) == x₁_tf, (x₁_tf)
    x₃(tf) == x₃_tf, (x₃_tf)

    # dynamics
    ẋ(t) == dynamics(x(t), u(t))

    # objective
    x₂(tf) → min
end

OptimalControl, scalarized ​

valid

The same continuous problem, written with scalar components only, as needed by the ExaModels modeler on CPU and GPU. Load OptimalControl and MadNLP.

Get and solve ​

julia
using OptimalControl, OptimalControlProblems
using MadNLP

pb = chain(OptimalControlScalarizedBackend())
sol = solve(
    model(pb), :collocation, :exa, :madnlp;
    init=initial_guess(pb),
    grid_size=500,
    scheme=:trapeze,
)
objective(sol)

The model ​

The model as written in ext/OptimalControlScalarizedModels/chain.jl, where the parameters are read from the metadata.

julia
ocp = @def begin
    t ∈ [t0, tf], time
    x ∈ R³, state
    u ∈ R, control

    # initial conditions
    x₁(t0) == x₁_t0, (x₁_t0)
    x₂(t0) == x₂_t0, (x₂_t0)
    x₃(t0) == x₃_t0, (x₃_t0)

    # final conditions
    x₁(tf) == x₁_tf, (x₁_tf)
    x₃(tf) == x₃_tf, (x₃_tf)

    # dynamics
    ∂(x₁)(t) == u(t)
    ∂(x₂)(t) == x₁(t) * √(1 + u(t)^2)
    ∂(x₃)(t) == √(1 + u(t)^2)

    # objective
    x₂(tf) → min
end

JuMP ​

valid

A JuMP model, already discretized: the scheme and the grid are chosen when the problem is built. Load JuMP and Ipopt.

Get and solve ​

julia
using JuMP, Ipopt, OptimalControlProblems

nlp = chain(
    JuMPBackend();
    grid_size=500,
    scheme=:trapeze,
)
set_optimizer(nlp, Ipopt.Optimizer)
optimize!(nlp)
objective_value(nlp)

The model ​

The model as written in ext/JuMPModels/chain.jl, where the parameters are read from the metadata.

julia
data = ProblemData(;
    state=[
        Component("x₁"),
        Component("x₂"),
        Component("x₃"),
    ],
    control=[Component("u")],
    costate=["∂x₁", "∂x₂", "∂x₃"],
    times=v -> (t0, tf),
    dynamics=(x, u, v, t) -> [u[1], x[1] * √(1 + u[1]^2), √(1 + u[1]^2)],
    cost=(I, x0, xf, v) -> xf[2],
    boundary=[
        (x₁_t0, (x0, xf, v) -> x0[1], x₁_t0),
        (x₂_t0, (x0, xf, v) -> x0[2], x₂_t0),
        (x₃_t0, (x0, xf, v) -> x0[3], x₃_t0),
        (x₁_tf, (x0, xf, v) -> xf[1], x₁_tf),
        (x₃_tf, (x0, xf, v) -> xf[3], x₃_tf),
    ],
)

Comparison of the modelings ​

Same problem ​

Two modelings of the same problem, discretized the same way, must give the same nonlinear program: same variables, constraints, objective and derivatives at the initial guess. This is what is compared, not the solutions: two solves are two optimization paths.

  • OptimalControl, scalarized and OptimalControl: same NLP, checked on every pull request.

  • JuMP and OptimalControl: same NLP, checked on every pull request.
