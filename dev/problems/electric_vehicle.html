Electric vehicle ​

  • 2 state
  • 1 control
  • Lagrange cost
  • fixed final time
  • 4 boundary
  • OptimalControl valid
  • OptimalControl, scalarized valid
  • JuMP valid

The Electric Vehicle (EV) trajectory problem is a benchmark in optimal control for energy-efficient driving. It was introduced by Petit & Sciarretta (2011) as a simplified longitudinal model of an electric vehicle moving along a road with varying slope. The state variables are the vehicle position and velocity , and the control represents the traction/braking command. The objective is to minimise a combination of mechanical energy consumption and control effort, subject to boundary conditions on the trip distance and vehicle velocity over a fixed horizon.

Qualitative behaviour ​

  • The optimal solution balances traction and braking to respect the velocity boundary conditions while minimising energy consumption.

  • Road slope variations introduce nonlinearities, strongly influencing the structure of the optimal control.

  • For flat roads, the solution often exhibits a bang–singular–bang profile, while slopes lead to asymmetric trajectories.

Characteristics ​

  • Nonlinear second-order dynamics including drag, gravity, and slope effects.

  • Mixed linear–quadratic cost reflecting energy and smoothness trade-offs.

  • Fixed-time (  s), fixed-distance trip with zero final velocity.

  • Benchmark for testing energy-optimal trajectory generation and direct transcription methods in electric vehicles.

References ​

  • Petit, N., & Sciarretta, A. (2011). Optimal drive of electric vehicles using an inversion-based trajectory generation approach. IFAC Proceedings Volumes, 44(1), 14519–14526. Introduces the EV optimal control formulation, including energy-efficient trajectory generation and numerical solution methods.

  • Sciarretta, A., & Guzzella, L. (2007). Control of Hybrid Electric Vehicles. IEEE Control Systems Magazine, 27(2), 60–70. Provides context for energy-optimal vehicle control and modelling of longitudinal dynamics.

  • Feng, X., & Petrovic, D. (2010). Energy-optimal control of electric vehicles: A review of recent advances. IEEE Transactions on Intelligent Transportation Systems, 11(3), 678–689. Surveys numerical methods for EV trajectory optimisation, including handling of road slopes and energy costs.

OptimalControl ​

valid

The continuous problem, written with the @def syntax of OptimalControl.jl, discretized and solved by OptimalControl.solve. Load OptimalControl and NLPModelsIpopt.

Get and solve ​

julia
using OptimalControl, OptimalControlProblems
using NLPModelsIpopt

pb = electric_vehicle(OptimalControlBackend())
sol = solve(
    model(pb), :collocation, :adnlp, :ipopt;
    init=initial_guess(pb),
    grid_size=500,
    scheme=:trapeze,
)
objective(sol)

The model ​

The model as written in ext/OptimalControlModels/electric_vehicle.jl, where the parameters are read from the metadata.

julia
ocp = @def begin
    t ∈ [t0, tf], time
    y = (x, v) ∈ R², state
    u ∈ R, control

    x(t0) == x_t0, (x_t0)
    v(t0) == v_t0, (v_t0)
    x(tf) == x_tf, (x_tf)
    v(tf) == v_tf, (v_tf)

    ẏ(t) == dynamics(x(t), v(t), u(t))

    ∫(b1 * u(t) * v(t) + b2 * u(t)^2) → min
end

OptimalControl, scalarized ​

valid

The same continuous problem, written with scalar components only, as needed by the ExaModels modeler on CPU and GPU. Load OptimalControl and MadNLP.

Get and solve ​

julia
using OptimalControl, OptimalControlProblems
using MadNLP

pb = electric_vehicle(OptimalControlScalarizedBackend())
sol = solve(
    model(pb), :collocation, :exa, :madnlp;
    init=initial_guess(pb),
    grid_size=500,
    scheme=:trapeze,
)
objective(sol)

The model ​

The model as written in ext/OptimalControlScalarizedModels/electric_vehicle.jl, where the parameters are read from the metadata.

julia
ocp = @def begin
    t ∈ [t0, tf], time
    y = (x, v) ∈ R², state
    u ∈ R, control

    x(t0) == x_t0, (x_t0)
    v(t0) == v_t0, (v_t0)
    x(tf) == x_tf, (x_tf)
    v(tf) == v_tf, (v_tf)

    road = α0 + α1 * x(t) + α2 * x(t)^2 + α3 * x(t)^3
    ∂(x)(t) == v(t)
    ∂(v)(t) == h1 * u(t) - h2 * v(t)^2 - h0 - road

    ∫(b1 * u(t) * v(t) + b2 * u(t)^2) → min
end

JuMP ​

valid

A JuMP model, already discretized: the scheme and the grid are chosen when the problem is built. Load JuMP and Ipopt.

Get and solve ​

julia
using JuMP, Ipopt, OptimalControlProblems

nlp = electric_vehicle(
    JuMPBackend();
    grid_size=500,
    scheme=:trapeze,
)
set_optimizer(nlp, Ipopt.Optimizer)
optimize!(nlp)
objective_value(nlp)

The model ​

The model as written in ext/JuMPModels/electric_vehicle.jl, where the parameters are read from the metadata.

julia
data = ProblemData(;
    state=[Component("x"), Component("v")],
    control=[Component("u")],
    costate=["∂x", "∂v"],
    times=v -> (t0, tf),
    dynamics=(x, u, v, t) -> dynamics(x, u),
    lagrange=(x, u, v, t) -> b1 * u[1] * x[2] + b2 * u[1]^2,
    boundary=[
        (x_t0, (x0, xf, v) -> x0[1], x_t0),
        (v_t0, (x0, xf, v) -> x0[2], v_t0),
        (x_tf, (x0, xf, v) -> xf[1], x_tf),
        (v_tf, (x0, xf, v) -> xf[2], v_tf),
    ],
)

Comparison of the modelings ​

Same problem ​

Two modelings of the same problem, discretized the same way, must give the same nonlinear program: same variables, constraints, objective and derivatives at the initial guess. This is what is compared, not the solutions: two solves are two optimization paths.

  • OptimalControl, scalarized and OptimalControl: same NLP, checked on every pull request.

  • JuMP and OptimalControl: same NLP, checked on every pull request.
