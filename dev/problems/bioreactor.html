The photobioreactor–digester system problem is a benchmark in constrained optimal control. It models the coupled dynamics of a microalgae photobioreactor and an anaerobic digester for methane production. The system includes three state variables: the algae concentration , the substrate concentration , and the biomass concentration . The control variable represents the input flow rate between the two units. The goal is to maximise methane production over a fixed horizon while satisfying biological and operational constraints Bayen et al. 2014.

Qualitative behaviour ​

The optimal solution exploits the periodic light–dark structure: algal growth is favoured during illuminated phases, while methane production dominates during dark phases. The control typically exhibits a bang–bang structure, alternating between minimum and maximum values, with possible singular arcs when substrate and biomass reach balanced levels. The positivity constraint on biomass is usually active at the beginning of the process, shaping the initial control action.

Characteristics ​

  • Nonlinear coupled dynamics with periodic forcing,

  • Control and state constraints ensuring feasibility,

  • Bang–bang and singular arc structures in the optimal control,

  • Serves as a benchmark for optimal control methods with periodic and constrained systems.

References ​

Optimal Control Applications and Methods. doi.org/10.1002/oca.2127 This paper analyses a periodic optimal control problem modelling a coupled microalgae photobioreactor and anaerobic digester. It provides theoretical insights and numerical solutions for maximising methane production under biological and operational constraints.

OptimalControl ​

valid

The continuous problem, written with the @def syntax of OptimalControl.jl, discretized and solved by OptimalControl.solve. Load OptimalControl and NLPModelsIpopt.

Get and solve ​

julia
using OptimalControl, OptimalControlProblems
using NLPModelsIpopt

pb = bioreactor(OptimalControlBackend())
sol = solve(
    model(pb), :collocation, :adnlp, :ipopt;
    init=initial_guess(pb),
    grid_size=600,
    scheme=:trapeze,
)
objective(sol)

The model ​

The model as written in ext/OptimalControlModels/bioreactor.jl, where the parameters are read from the metadata.

julia
ocp = @def begin
    t ∈ [t0, tf], time
    x = (y, s, b) ∈ R³, state
    u ∈ R, control

    x(t) ≥ [y_l, s_l, b_l]
    u_l ≤ u(t) ≤ u_u
    [y_t0_l, s_t0_l, b_t0_l] ≤ x(t0) ≤ [y_t0_u, s_t0_u, b_t0_u]

    μ = light(t, halfperiod) * μbar
    μ2 = growth(s(t), μ2m, Ks)

    ẋ(t) == [
        μ * y(t) / (1 + y(t)) - (r + u(t)) * y(t),
        -μ2 * b(t) + u(t) * β * (γ * y(t) - s(t)),
        (μ2 - u(t) * β) * b(t),
    ]

    -∫(μ2 * b(t) / (β + c)) → min
end

JuMP ​

valid

A JuMP model, already discretized: the scheme and the grid are chosen when the problem is built. Load JuMP and Ipopt.

Get and solve ​

julia
using JuMP, Ipopt, OptimalControlProblems

nlp = bioreactor(
    JuMPBackend();
    grid_size=600,
    scheme=:trapeze,
)
set_optimizer(nlp, Ipopt.Optimizer)
optimize!(nlp)
objective_value(nlp)

The model ​

The model as written in ext/JuMPModels/bioreactor.jl, where the parameters are read from the metadata.

julia
data = ProblemData(;
    state=[
        Component("y"; lower=y_l),
        Component("s"; lower=s_l),
        Component("b"; lower=b_l),
    ],
    control=[Component("u"; lower=u_l, upper=u_u)],
    costate=["∂y", "∂s", "∂b"],
    times=v -> (t0, tf),
    dynamics=(x, u, v, t) -> dynamics(x, u, t),
    lagrange=(x, u, v, t) -> μ2m * x[2] / (x[2] + Ks) * x[3] / (β + c),
    cost=(I, x0, xf, v) -> -I,
    boundary=[
        (y_t0_l, (x0, xf, v) -> x0[1], y_t0_u),
        (s_t0_l, (x0, xf, v) -> x0[2], s_t0_u),
        (b_t0_l, (x0, xf, v) -> x0[3], b_t0_u),
    ],
)

Comparison of the modelings ​

Same problem ​

Two modelings of the same problem, discretized the same way, must give the same nonlinear program: same variables, constraints, objective and derivatives at the initial guess. This is what is compared, not the solutions: two solves are two optimization paths.

  • JuMP and OptimalControl: same NLP, checked on every pull request.
