The robot arm motion problem is a benchmark in time-optimal control. It models a robotic arm moving between two points in space, represented as a rigid bar of total length pivoting at the origin of a spherical coordinate system. The system includes six state variables: the radial position and its velocity , the horizontal angle and its angular velocity , and the vertical angle and its angular velocity . The control variables are , , and , representing the forces or torques applied along the radial and angular directions. The objective is to minimise the total transfer time while satisfying state and control constraints BOCOP Robot Arm Example.

Qualitative behaviour ​

The optimal solution exploits the degrees of freedom of the spherical coordinate system to minimise the motion time. Control inputs , , and typically follow bang–bang profiles, alternating between maximum and minimum values to reach the target efficiently. The dynamics are nonlinear due to the dependence of the moments of inertia and on the radial and angular positions, which affects the acceleration of the arm.

Characteristics ​

  • Nonlinear, second-order dynamics in spherical coordinates,

  • Free final time with state and control constraints,

  • Bang–bang control structure in the time-optimal solution,

  • Serves as a benchmark for direct transcription and NLP solvers in robotic motion planning.

References ​

  • Mössner-Beigel, M. (1989). Thesis, Heidelberg University. Introduces the time-optimal robotic arm problem and its theoretical formulation.

  • Vanderbei, R. J. (2001). Case studies in trajectory optimization: Trains, Planes, and Other Pastimes. Provides numerical strategies for robotic motion planning and discusses control substitution techniques for time-optimal trajectories.

  • BOCOP examples: Robot arm problem. BOCOP Robot Arm Example Demonstrates the practical implementation using direct transcription and NLP solvers for robotic motion problems.

OptimalControl ​

valid

The continuous problem, written with the @def syntax of OptimalControl.jl, discretized and solved by OptimalControl.solve. Load OptimalControl and NLPModelsIpopt.

Get and solve ​

julia
using OptimalControl, OptimalControlProblems
using NLPModelsIpopt

pb = robot(OptimalControlBackend())
sol = solve(
    model(pb), :collocation, :adnlp, :ipopt;
    init=initial_guess(pb),
    grid_size=250,
    scheme=:trapeze,
)
objective(sol)

The model ​

The model as written in ext/OptimalControlModels/robot.jl, where the parameters are read from the metadata.

julia
ocp = @def begin
    tf ∈ R, variable
    t ∈ [t0, tf], time
    x = (ρ, dρ, θ, dθ, ϕ, dϕ) ∈ R⁶, state
    u = (uρ, uθ, uϕ) ∈ R³, control

    tf ≥ tf_l

    # state constraints
    ρ_l ≤ ρ(t) ≤ ρ_u, (ρ_c)
    θ_l ≤ θ(t) ≤ θ_u, (θ_c)
    ϕ_l ≤ ϕ(t) ≤ ϕ_u, (ϕ_c)

    # control constraints
    uρ_l ≤ uρ(t) ≤ uρ_u, (u_ρ_c)
    uθ_l ≤ uθ(t) ≤ uθ_u, (u_θ_c)
    uϕ_l ≤ uϕ(t) ≤ uϕ_u, (u_ϕ_c)

    # initial conditions
    ρ(t0) == ρ_t0, (ρ_t0)
    θ(t0) == θ_t0, (θ_t0)
    ϕ(t0) == ϕ_t0, (ϕ_t0)
    dρ(t0) == dρ_t0, (dρ_t0)
    dθ(t0) == dθ_t0, (dθ_t0)
    dϕ(t0) == dϕ_t0, (dϕ_t0)

    # final conditions
    ρ(tf) == ρ_tf, (ρ_tf)
    θ(tf) == θ_tf, (θ_tf)
    ϕ(tf) == ϕ_tf, (ϕ_tf)
    dρ(tf) == dρ_tf, (dρ_tf)
    dθ(tf) == dθ_tf, (dθ_tf)
    dϕ(tf) == dϕ_tf, (dϕ_tf)

    I_θ = ((L - ρ(t))^3 + ρ(t)^3) * (sin(ϕ(t))^2 + 1e-9)
    I_ϕ = (L - ρ(t))^3 + ρ(t)^3

    # dynamics  
    ẋ(t) == [dρ(t), uρ(t) / L, dθ(t), 3 * uθ(t) / I_θ, dϕ(t), 3 * uϕ(t) / I_ϕ]

    # objective
    tf → min
end

OptimalControl, scalarized ​

valid

The same continuous problem, written with scalar components only, as needed by the ExaModels modeler on CPU and GPU. Load OptimalControl and MadNLP.

Get and solve ​

julia
using OptimalControl, OptimalControlProblems
using MadNLP

pb = robot(OptimalControlScalarizedBackend())
sol = solve(
    model(pb), :collocation, :exa, :madnlp;
    init=initial_guess(pb),
    grid_size=250,
    scheme=:trapeze,
)
objective(sol)

JuMP ​

valid

A JuMP model, already discretized: the scheme and the grid are chosen when the problem is built. Load JuMP and Ipopt.

Get and solve ​

julia
using JuMP, Ipopt, OptimalControlProblems

nlp = robot(
    JuMPBackend();
    grid_size=250,
    scheme=:trapeze,
)
set_optimizer(nlp, Ipopt.Optimizer)
optimize!(nlp)
objective_value(nlp)

The model ​

The model as written in ext/JuMPModels/robot.jl, where the parameters are read from the metadata.

julia
data = ProblemData(;
    state=[
        Component("ρ"; lower=ρ_l, upper=ρ_u),
        Component("dρ"),
        Component("θ"; lower=θ_l, upper=θ_u),
        Component("dθ"),
        Component("ϕ"; lower=ϕ_l, upper=ϕ_u),
        Component("dϕ"),
    ],
    control=[
        Component("uρ"; lower=uρ_l, upper=uρ_u),
        Component("uθ"; lower=uθ_l, upper=uθ_u),
        Component("uϕ"; lower=uϕ_l, upper=uϕ_u),
    ],
    variable=[Component("tf"; lower=tf_l)],
    costate=["∂ρ", "∂dρ", "∂θ", "∂dθ", "∂ϕ", "∂dϕ"],
    times=v -> (t0, v[1]),
    dynamics=(x, u, v, t) -> dynamics(x, u),
    cost=(I, x0, xf, v) -> v[1],
    boundary=[
        (ρ_t0, (x0, xf, v) -> x0[1], ρ_t0),
        (θ_t0, (x0, xf, v) -> x0[3], θ_t0),
        (ϕ_t0, (x0, xf, v) -> x0[5], ϕ_t0),
        (dρ_t0, (x0, xf, v) -> x0[2], dρ_t0),
        (dθ_t0, (x0, xf, v) -> x0[4], dθ_t0),
        (dϕ_t0, (x0, xf, v) -> x0[6], dϕ_t0),
        (ρ_tf, (x0, xf, v) -> xf[1], ρ_tf),
        (θ_tf, (x0, xf, v) -> xf[3], θ_tf),
        (ϕ_tf, (x0, xf, v) -> xf[5], ϕ_tf),
        (dρ_tf, (x0, xf, v) -> xf[2], dρ_tf),
        (dθ_tf, (x0, xf, v) -> xf[4], dθ_tf),
        (dϕ_tf, (x0, xf, v) -> xf[6], dϕ_tf),
    ],
)

Comparison of the modelings ​

Same problem ​

Two modelings of the same problem, discretized the same way, must give the same nonlinear program: same variables, constraints, objective and derivatives at the initial guess. This is what is compared, not the solutions: two solves are two optimization paths.

  • OptimalControl, scalarized and OptimalControl: same NLP, checked on every pull request.

  • JuMP and OptimalControl: same NLP, checked on every pull request.
