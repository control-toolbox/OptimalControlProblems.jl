Bryson denham ​

  • 2 state
  • 1 control
  • Lagrange cost
  • fixed final time
  • 1 state box
  • 4 boundary
  • OptimalControl valid
  • OptimalControl, scalarized valid
  • JuMP draft
  • ModelingToolkit valid

The Bryson–Denham problem is a classic optimal control benchmark involving a state inequality constraint. It models the movement of a unit mass on a frictionless plane, where the goal is to relocate the mass over a fixed time interval with minimum control effort, while ensuring the position never exceeds a certain limit. Originally introduced in Bryson et al. 1963, it is a standard test case for evaluating the ability of numerical solvers to handle state-constrained trajectories.

Mathematical formulation ​

The problem can be stated as

\begin{aligned} \min_{x,u} \quad & J(x,u) = \frac{1}{2} \int_0^1 u^2(t) ,\mathrm{d}t \ \text{s.t.} \quad & \dot{x}_1(t) = x_2(t), \quad \dot{x}_2(t) = u(t), \ & x_1(0) = 0, ; x_1(1) = 0, ; x_2(0) = 1, ; x_2(1) = -1, \ & x_1(t) \le a. \end

where represents position, velocity, acceleration (control), and is the maximum allowable displacement (e.g.,  ).

Qualitative behaviour ​

The problem features a second-order state constraint because the control only appears in the second derivative of the constrained state :

\ddot{x}_1(t) = u(t).

When the trajectory is on a boundary arc ( ), the derivatives and must be zero. This implies that while the constraint is active, the velocity is zero and the control is zero:

u(t) = 0.

The solution structure changes based on the value of the constraint parameter :

  • Unconstrained Case: If is sufficiently large ( ), the state constraint is never active.

  • Touch Point: For a critical value of , the trajectory just touches the boundary   at a single point  .

  • Boundary Arc: For smaller values (e.g.,  ), the trajectory remains on the boundary for a finite time interval. During this interval, the control vanishes.

Characteristics ​

  • Linear–quadratic dynamics with a second-order state inequality constraint.

  • Demonstrates a "bang-off-bang" control structure where the control is zero on the constraint boundary.

  • Used to test the accuracy of state constraint handling and the detection of switching times.

References ​

  • Bryson, A.E., Denham, W.F., & Dreyfus, S.E. (1963). Optimal programming problems with inequality constraints I: necessary conditions for extremal solutions. AIAA Journal. doi.org/10.2514/3.2107

  • Dymos Documentation: Bryson-Denham Problem. dymos/examples/bryson_denham

OptimalControl ​

valid

The continuous problem, written with the @def syntax of OptimalControl.jl, discretized and solved by OptimalControl.solve. Load OptimalControl and NLPModelsIpopt.

Get and solve ​

julia
using OptimalControl, OptimalControlProblems
using NLPModelsIpopt

pb = bryson_denham(OptimalControlBackend())
sol = solve(
    model(pb), :collocation, :adnlp, :ipopt;
    init=initial_guess(pb),
    grid_size=500,
    scheme=:trapeze,
)
objective(sol)

The model ​

The model as written in ext/OptimalControlModels/bryson_denham.jl, where the parameters are read from the metadata.

julia
ocp = @def begin
    t ∈ [t0, tf], time
    x ∈ R², state
    u ∈ R, control

    x(t0) == [x1_t0, x2_t0]
    x(tf) == [x1_tf, x2_tf]

    x₁(t) ≤ x1_max

    ẋ(t) == [x₂(t), u(t)]

    ∫(0.5 * u(t)^2) → min
end

JuMP ​

draft

A JuMP model, already discretized: the scheme and the grid are chosen when the problem is built. Load JuMP and Ipopt.

Draft in this modeling

The problem is not validated in this modeling yet: JuMP uses ASCII state component names while the OptimalControl model uses Unicode names. Getting it warns, and it is left out of problems(JuMPBackend()).

Get and solve ​

julia
using JuMP, Ipopt, OptimalControlProblems

nlp = bryson_denham(
    JuMPBackend();
    grid_size=500,
    scheme=:trapeze,
)
set_optimizer(nlp, Ipopt.Optimizer)
optimize!(nlp)
objective_value(nlp)

The model ​

The model as written in ext/JuMPModels/bryson_denham.jl, where the parameters are read from the metadata.

julia
data = ProblemData(;
    state=[Component("x1"; upper=x1_max), Component("x2")],
    control=[Component("u")],
    costate=["p1", "p2"],
    times=v -> (t0, tf),
    dynamics=(x, u, v, t) -> [x[2], u[1]],
    lagrange=(x, u, v, t) -> 0.5 * u[1]^2,
    boundary=[
        (x1_t0, (x0, xf, v) -> x0[1], x1_t0),
        (x2_t0, (x0, xf, v) -> x0[2], x2_t0),
        (x1_tf, (x0, xf, v) -> xf[1], x1_tf),
        (x2_tf, (x0, xf, v) -> xf[2], x2_tf),
    ],
)

Comparison of the modelings ​

Same problem ​

Two modelings of the same problem, discretized the same way, must give the same nonlinear program: same variables, constraints, objective and derivatives at the initial guess. This is what is compared, not the solutions: two solves are two optimization paths.

  • OptimalControl, scalarized and OptimalControl: same NLP, checked on every pull request.

  • JuMP and OptimalControl: not checked yet: the problem is a draft in JuMP.

  • ModelingToolkit and OptimalControl: same NLP, checked on every pull request.
