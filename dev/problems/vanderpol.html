The Van der Pol oscillator control problem is a benchmark in nonlinear optimal control. It models a two-dimensional oscillator with nonlinear damping and a control input. The state vector is  , and the control variable is . The goal is to minimise a quadratic cost functional over a fixed horizon   while steering the system from a given initial condition.

Qualitative behaviour ​

  • The optimal control regulates the nonlinear oscillations to minimise both state excursions and control effort.

  • Due to the quadratic cost, the control is typically smooth, without bang–bang or singular arcs.

  • Serves as a standard test for direct transcription methods and numerical solvers for nonlinear optimal control problems.

Characteristics ​

  • Two-dimensional nonlinear dynamics with cubic damping,

  • Quadratic cost on both states and control,

  • Fixed final time,

  • Unconstrained control (extensions may include bounds),

  • Useful benchmark for testing optimal control algorithms and integration schemes.

OptimalControl ​

valid

The continuous problem, written with the @def syntax of OptimalControl.jl, discretized and solved by OptimalControl.solve. Load OptimalControl and NLPModelsIpopt.

Get and solve ​

julia
using OptimalControl, OptimalControlProblems
using NLPModelsIpopt

pb = vanderpol(OptimalControlBackend())
sol = solve(
    model(pb), :collocation, :adnlp, :ipopt;
    init=initial_guess(pb),
    grid_size=500,
    scheme=:trapeze,
)
objective(sol)

The model ​

The model as written in ext/OptimalControlModels/vanderpol.jl, where the parameters are read from the metadata.

julia
ocp = @def begin
    t ∈ [t0, tf], time
    x ∈ R², state
    u ∈ R, control

    x(t0) == [x₁_t0, x₂_t0]

    ẋ(t) == [x[2](t), ε * ω * (1 - x[1](t)^2) * x[2](t) - ω^2 * x[1](t) + u(t)]

    0.5∫(x[1](t)^2 + x[2](t)^2 + u(t)^2) → min
end

JuMP ​

valid

A JuMP model, already discretized: the scheme and the grid are chosen when the problem is built. Load JuMP and Ipopt.

Get and solve ​

julia
using JuMP, Ipopt, OptimalControlProblems

nlp = vanderpol(
    JuMPBackend();
    grid_size=500,
    scheme=:trapeze,
)
set_optimizer(nlp, Ipopt.Optimizer)
optimize!(nlp)
objective_value(nlp)

The model ​

The model as written in ext/JuMPModels/vanderpol.jl, where the parameters are read from the metadata.

julia
data = ProblemData(;
    state=[Component("x₁"), Component("x₂")],
    control=[Component("u")],
    costate=["∂x₁", "∂x₂"],
    times=v -> (t0, tf),
    dynamics=(x, u, v, t) -> [x[2], ε * ω * (1 - x[1]^2) * x[2] - ω^2 * x[1] + u[1]],
    lagrange=(x, u, v, t) -> 0.5 * (x[1]^2 + x[2]^2 + u[1]^2),
    boundary=[
        (x₁_t0, (x0, xf, v) -> x0[1], x₁_t0), (x₂_t0, (x0, xf, v) -> x0[2], x₂_t0)
    ],
)

ModelingToolkit ​

valid

The continuous problem, written as a ModelingToolkit.jl System with its costs and constraints. The tests solve it by direct single shooting with Corleone.jl: the controls are piecewise constant and the state path constraints are imposed at the nodes of the grid; these choices are not part of the model, so the snippet stops at the model. Load ModelingToolkit.

Get and solve ​

julia
using ModelingToolkit, OptimalControlProblems

pb = vanderpol(ModelingToolkitBackend())
sys = model(pb)          # a ModelingToolkit.System
init = initial_guess(pb) # the initial guess of the problem

The model ​

julia
ModelingToolkit.@named sys = ModelingToolkit.System(

Comparison of the modelings ​

Same problem ​

Two modelings of the same problem, discretized the same way, must give the same nonlinear program: same variables, constraints, objective and derivatives at the initial guess. This is what is compared, not the solutions: two solves are two optimization paths.

  • OptimalControl, scalarized and OptimalControl: same NLP, checked on every pull request.

  • JuMP and OptimalControl: same NLP, checked on every pull request.
