The clamped beam problem is a classical benchmark in constrained optimal control. It models the deflection of a flexible beam that is fixed (clamped) at both ends and subject to an external force. Originating from the Euler–Bernoulli beam model Bryson et al. 1963, it is widely used in benchmark suites. Both the state trajectory   and the control   are decision variables, and the aim is to minimise the control effort under boundary conditions and a state inequality constraint on the beam deflection.

Qualitative behaviour ​

This problem involves a second-order state constraint. Differentiating the inequality twice reveals that the control is directly related to the curvature of the state:

Along a boundary arc, where remains constant, both derivatives vanish. Consequently, the control along such an arc is zero:

In optimal control terminology, a touch point refers to the case where the state hits the bound at a single instant, while a boundary arc designates an interval where the state remains on the bound.

The qualitative behaviour of the optimal trajectory depends on the parameter :

  • Case 1:  . The inequality constraint is inactive. The optimal solution is simply the unconstrained trajectory:    .

  • Case 2:   . The trajectory touches the boundary exactly once (a touch point) at  . There is no interval of constraint activation, but the single contact reflects the influence of the state bound.

  • Case 3:  . A boundary arc appears: the state constraint is active over a finite interval. Along this interval, the control vanishes:  .

These cases illustrate how second-order state inequality constraints can yield unconstrained solutions, isolated touch points, or extended boundary arcs, thereby shaping both the trajectory and the control.

Characteristics ​

  • Linear–quadratic dynamics and cost.

  • State inequality constraint induces either unconstrained motion, touch points, or boundary arcs depending on the parameter .

  • Serves as a benchmark for optimal control methods handling state constraints.

References ​

  • Bryson, A.E., Denham, W.F., & Dreyfus, S.E. (1963). Optimal programming problems with inequality constraints I: necessary conditions for extremal solutions. AIAA Journal. doi.org/10.2514/3.2107 This seminal work develops the theoretical foundation for optimal control problems with inequality constraints, including the derivation of necessary conditions for extremal solutions. It provides the basis for analysing state-constrained control problems like the clamped beam.

  • BOCOP examples: Clamped Beam problem. Examples-BOCOP.pdf This example illustrates the practical implementation of the clamped beam problem in BOCOP, providing a benchmark for testing optimal control methods under state inequality constraints.

OptimalControl ​

valid

The continuous problem, written with the @def syntax of OptimalControl.jl, discretized and solved by OptimalControl.solve. Load OptimalControl and NLPModelsIpopt.

Get and solve ​

julia
using OptimalControl, OptimalControlProblems
using NLPModelsIpopt

pb = beam(OptimalControlBackend())
sol = solve(
    model(pb), :collocation, :adnlp, :ipopt;
    init=initial_guess(pb),
    grid_size=500,
    scheme=:trapeze,
)
objective(sol)

The model ​

The model as written in ext/OptimalControlModels/beam.jl, where the parameters are read from the metadata.

julia
ocp = @def begin
    t ∈ [t0, tf], time
    x ∈ R², state
    u ∈ R, control

    x(t0) == [x₁_t0, x₂_t0]
    x(tf) == [x₁_tf, x₂_tf]
    x₁_l ≤ x₁(t) ≤ x₁_u

    ẋ(t) == [x₂(t), u(t)]

    ∫(u(t)^2) → min
end

valid

JuMP ​

valid

A JuMP model, already discretized: the scheme and the grid are chosen when the problem is built. Load JuMP and Ipopt.

Get and solve ​

julia
using JuMP, Ipopt, OptimalControlProblems

nlp = beam(
    JuMPBackend();
    grid_size=500,
    scheme=:trapeze,
)
set_optimizer(nlp, Ipopt.Optimizer)
optimize!(nlp)
objective_value(nlp)

The model ​

The model as written in ext/JuMPModels/beam.jl, where the parameters are read from the metadata.

julia
data = ProblemData(;
    state=[
        Component("x₁"; lower=x₁_l, upper=x₁_u), Component("x₂")
    ],
    control=[Component("u")],
    costate=["∂x₁", "∂x₂"],
    times=v -> (t0, tf),
    dynamics=(x, u, v, t) -> [x[2], u[1]],
    lagrange=(x, u, v, t) -> u[1]^2,
    boundary=[
        (x₁_t0, (x0, xf, v) -> x0[1], x₁_t0),
        (x₂_t0, (x0, xf, v) -> x0[2], x₂_t0),
        (x₁_tf, (x0, xf, v) -> xf[1], x₁_tf),
        (x₂_tf, (x0, xf, v) -> xf[2], x₂_tf),
    ],
)

Comparison of the modelings ​

Same problem ​

Two modelings of the same problem, discretized the same way, must give the same nonlinear program: same variables, constraints, objective and derivatives at the initial guess. This is what is compared, not the solutions: two solves are two optimization paths.

  • OptimalControl, scalarized and OptimalControl: same NLP, checked on every pull request.

  • JuMP and OptimalControl: same NLP, checked on every pull request.
