The Moonlander optimal control problem is a benchmark in constrained optimal control. It models the powered descent of a spacecraft aiming to land on a specified target on the Moon's surface in minimum time. The system comprises six state variables: the horizontal position , vertical position , horizontal velocity , vertical velocity , orientation angle , and angular velocity . The control variables and represent the thrust forces applied by the lander's engines. The objective is to minimise the final time while ensuring a soft landing at the target, subject to control and physical constraints.

Qualitative behaviour ​

The optimal solution typically exhibits a bang–bang structure, where thrusts switch between minimum and maximum values, ensuring minimal landing time while satisfying position and velocity constraints. Orientation dynamics and play a critical role in directing the thrust to achieve the target.

Characteristics ​

  • Nonlinear coupled dynamics with orientation-dependent thrust,

  • Control constraints and bounded final time ensuring feasibility,

  • Terminal position and velocity constraints for a soft landing,

  • Benchmark problem for testing direct transcription and NLP solvers.

OptimalControl ​

valid

The continuous problem, written with the @def syntax of OptimalControl.jl, discretized and solved by OptimalControl.solve. Load OptimalControl and NLPModelsIpopt.

Get and solve ​

julia
using OptimalControl, OptimalControlProblems
using NLPModelsIpopt

pb = moonlander(OptimalControlBackend())
sol = solve(
    model(pb), :collocation, :adnlp, :ipopt;
    init=initial_guess(pb),
    grid_size=500,
    scheme=:trapeze,
)
objective(sol)

The model ​

The model as written in ext/OptimalControlModels/moonlander.jl, where the parameters are read from the metadata.

julia
ocp = @def begin

    # state, control and final time variables, and time
    tf ∈ R, variable
    t ∈ [t0, tf], time
    x = (p₁, p₂, dp₁, dp₂, θ, dθ) ∈ R⁶, state
    u = (F₁, F₂) ∈ R², control

    # final time constraint
    tf_l ≤ tf ≤ tf_u

    # control constraints
    F₁_l ≤ F₁(t) ≤ F₁_u, (F₁_c)
    F₂_l ≤ F₂(t) ≤ F₂_u, (F₂_c)

    # initial conditions
    p₁(t0) == p₁_t0, (p₁_t0)
    p₂(t0) == p₂_t0, (p₂_t0)
    dp₁(t0) == dp₁_t0, (dp₁_t0)
    dp₂(t0) == dp₂_t0, (dp₂_t0)
    θ(t0) == θ_t0, (θ_t0)
    dθ(t0) == dθ_t0, (dθ_t0)

    # final conditions
    p₁(tf) == p₁_tf, (p₁_tf)
    p₂(tf) == p₂_tf, (p₂_tf)
    dp₁(tf) == dp₁_tf, (dp₁_tf)
    dp₂(tf) == dp₂_tf, (dp₂_tf)

    # dynamics
    ẋ(t) == dynamics(x(t), u(t))

    # objective
    tf → min
end

JuMP ​

valid

A JuMP model, already discretized: the scheme and the grid are chosen when the problem is built. Load JuMP and Ipopt.

Get and solve ​

julia
using JuMP, Ipopt, OptimalControlProblems

nlp = moonlander(
    JuMPBackend();
    grid_size=500,
    scheme=:trapeze,
)
set_optimizer(nlp, Ipopt.Optimizer)
optimize!(nlp)
objective_value(nlp)

The model ​

The model as written in ext/JuMPModels/moonlander.jl, where the parameters are read from the metadata.

julia
data = ProblemData(;
    state=[
        Component("p₁"),
        Component("p₂"),
        Component("dp₁"),
        Component("dp₂"),
        Component("θ"),
        Component("dθ"),
    ],
    control=[
        Component("F₁"; lower=F₁_l, upper=F₁_u),
        Component("F₂"; lower=F₂_l, upper=F₂_u),
    ],
    variable=[Component("tf"; lower=tf_l, upper=tf_u)],
    costate=["∂p₁", "∂p₂", "∂dp₁", "∂dp₂", "∂θ", "∂dθ"],
    times=v -> (t0, v[1]),
    dynamics=(x, u, v, t) -> dynamics(x, u),
    cost=(integral, x0, xf, v) -> v[1],
    boundary=[
        (p₁_t0, (x0, xf, v) -> x0[1], p₁_t0),
        (p₂_t0, (x0, xf, v) -> x0[2], p₂_t0),
        (dp₁_t0, (x0, xf, v) -> x0[3], dp₁_t0),
        (dp₂_t0, (x0, xf, v) -> x0[4], dp₂_t0),
        (θ_t0, (x0, xf, v) -> x0[5], θ_t0),
        (dθ_t0, (x0, xf, v) -> x0[6], dθ_t0),
        (p₁_tf, (x0, xf, v) -> xf[1], p₁_tf),
        (p₂_tf, (x0, xf, v) -> xf[2], p₂_tf),
        (dp₁_tf, (x0, xf, v) -> xf[3], dp₁_tf),
        (dp₂_tf, (x0, xf, v) -> xf[4], dp₂_tf),
    ],
)

Same problem ​

Two modelings of the same problem, discretized the same way, must give the same nonlinear program: same variables, constraints, objective and derivatives at the initial guess. This is what is compared, not the solutions: two solves are two optimization paths.
