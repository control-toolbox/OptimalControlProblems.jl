Dielectrophoretic particle ​

The dielectrophoretic particle problem is a classical time-optimal control benchmark for microfluidic particle manipulation. It models the motion of a particle under a dielectrophoretic force, where the control voltage applied to electrodes directly influences the particle trajectory. Both the particle position and an auxiliary state related to its dipole moment, as well as the control voltage, are decision variables. The objective is to transfer the particle from an initial position to a target position in minimal time, while satisfying bounds on the control input and maintaining the auxiliary state dynamics.

Qualitative behaviour ​

  • The optimal control typically saturates at the bounds   , characteristic of time-optimal problems.

  • The auxiliary state evolves according to both the control and its own decay, influencing the particle's acceleration nonlinearly.

  • The final time is free and is adjusted by the optimisation to achieve minimal transfer time.

Characteristics ​

  • Nonlinear dynamics with bilinear and quadratic terms in the control.

  • Time-optimal objective with control bounds.

  • Free end-time formulation.

  • Widely used as a benchmark in numerical optimal control for microfluidic particle manipulation.

OptimalControl ​

valid

The continuous problem, written with the @def syntax of OptimalControl.jl, discretized and solved by OptimalControl.solve. Load OptimalControl and NLPModelsIpopt.

Get and solve ​

julia
using OptimalControl, OptimalControlProblems
using NLPModelsIpopt

pb = dielectrophoretic_particle(OptimalControlBackend())
sol = solve(
    model(pb), :collocation, :adnlp, :ipopt;
    init=initial_guess(pb),
    grid_size=500,
    scheme=:trapeze,
)
objective(sol)

The model ​

The model as written in ext/OptimalControlModels/dielectrophoretic_particle.jl, where the parameters are read from the metadata.

julia
ocp = @def begin
    tf ∈ R, variable
    t ∈ [t0, tf], time
    q = (x, y) ∈ R², state
    u ∈ R, control

    x(t0) == x_t0, (x_t0)
    y(t0) == y_t0, (y_t0)
    x(tf) == x_tf, (x_tf)
    tf ≥ tf_l, (tf_c)
    u_l ≤ u(t) ≤ u_u, (u_c)

    q̇(t) == dynamics(y(t), u(t))

    tf → min
end

OptimalControl, scalarized ​

valid

The same continuous problem, written with scalar components only, as needed by the ExaModels modeler on CPU and GPU. Load OptimalControl and MadNLP.

Get and solve ​

julia
using OptimalControl, OptimalControlProblems
using MadNLP

pb = dielectrophoretic_particle(OptimalControlScalarizedBackend())
sol = solve(
    model(pb), :collocation, :exa, :madnlp;
    init=initial_guess(pb),
    grid_size=500,
    scheme=:trapeze,
)
objective(sol)

The model ​

The model as written in ext/OptimalControlScalarizedModels/dielectrophoretic_particle.jl, where the parameters are read from the metadata.

julia
ocp = @def begin
    tf ∈ R, variable
    t ∈ [t0, tf], time
    q = (x, y) ∈ R², state
    u ∈ R, control

    x(t0) == x_t0, (x_t0)
    y(t0) == y_t0, (y_t0)
    x(tf) == x_tf, (x_tf)
    tf ≥ tf_l, (tf_c)
    u_l ≤ u(t) ≤ u_u, (u_c)

    ∂(x)(t) == y(t) * u(t) + α * u(t)^2
    ∂(y)(t) == -c * y(t) + u(t)

    tf → min
end

JuMP ​

valid

A JuMP model, already discretized: the scheme and the grid are chosen when the problem is built. Load JuMP and Ipopt.

Get and solve ​

julia
using JuMP, Ipopt, OptimalControlProblems

nlp = dielectrophoretic_particle(
    JuMPBackend();
    grid_size=500,
    scheme=:trapeze,
)
set_optimizer(nlp, Ipopt.Optimizer)
optimize!(nlp)
objective_value(nlp)

The model ​

The model as written in ext/JuMPModels/dielectrophoretic_particle.jl, where the parameters are read from the metadata.

julia
data = ProblemData(;
    state=[Component("x"), Component("y")],
    control=[Component("u"; lower=u_l, upper=u_u)],
    variable=[Component("tf"; lower=tf_l)],
    costate=["∂x", "∂y"],
    times=v -> (t0, v[1]),
    dynamics=(x, u, v, t) -> [x[2] * u[1] + α * u[1]^2, -c * x[2] + u[1]],
    cost=(I, x0, xf, v) -> v[1],
    boundary=[
        (x_t0, (x0, xf, v) -> x0[1], x_t0),
        (y_t0, (x0, xf, v) -> x0[2], y_t0),
        (x_tf, (x0, xf, v) -> xf[1], x_tf),
    ],
)

Comparison of the modelings ​

Same problem ​

Two modelings of the same problem, discretized the same way, must give the same nonlinear program: same variables, constraints, objective and derivatives at the initial guess. This is what is compared, not the solutions: two solves are two optimization paths.

  • OptimalControl, scalarized and OptimalControl: same NLP, checked on every pull request.

  • JuMP and OptimalControl: same NLP, checked on every pull request.
