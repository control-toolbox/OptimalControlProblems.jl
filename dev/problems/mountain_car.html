Mountain car ​

  • 2 state
  • 1 control
  • 1 variable
  • Mayer cost
  • free final time
  • 2 state box
  • 1 control box
  • 1 variable box
  • 4 boundary
  • OptimalControl valid
  • OptimalControl, scalarized valid
  • JuMP valid

The Mountain Car problem is a classic benchmark in control and reinforcement learning. It involves an underpowered car that must climb a steep hill to reach a target position. Because the car's engine is too weak to climb the hill directly, it must first drive away from the goal to gain momentum by oscillating in a valley. The goal is to reach the target position in minimum time.

Qualitative behaviour ​

  • The car must oscillate back and forth in the valley to build enough kinetic energy to climb the right hill.

  • The optimal strategy typically involves a sequence of full-throttle accelerations in alternating directions (bang-bang control).

  • The minimum time objective makes the problem sensitive to the initial guess for the final time.

Characteristics ​

  • Two-dimensional state space (position and velocity),

  • Scalar control (effort/acceleration),

  • Free final time with minimum time objective,

  • State constraints (position and velocity bounds),

  • Control constraints (bounds on acceleration).

References ​

  • Dymos Documentation. The Mountain Car Problem. Provides a detailed description and implementation of the Mountain Car problem using the Dymos library.

  • OpenAI Gym. MountainCar-v0. A standard reinforcement learning environment for the Mountain Car problem.

  • Moore, A. W. (1990). Efficient Memory-based Learning for Robot Control. PhD thesis, University of Cambridge. Introduces the Mountain Car problem as a benchmark for reinforcement learning and control.

OptimalControl ​

valid

The continuous problem, written with the @def syntax of OptimalControl.jl, discretized and solved by OptimalControl.solve. Load OptimalControl and NLPModelsIpopt.

Get and solve ​

julia
using OptimalControl, OptimalControlProblems
using NLPModelsIpopt

pb = mountain_car(OptimalControlBackend())
sol = solve(
    model(pb), :collocation, :adnlp, :ipopt;
    init=initial_guess(pb),
    grid_size=200,
    scheme=:trapeze,
)
objective(sol)

The model ​

The model as written in ext/OptimalControlModels/mountain_car.jl, where the parameters are read from the metadata.

julia
ocp = @def begin
    tf ∈ R, variable
    t ∈ [t0, tf], time
    x = (pos, vel) ∈ R², state
    u ∈ R, control

    # constraints
    tf ≥ tf_min
    pos_min ≤ pos(t) ≤ pos_max
    vel_min ≤ vel(t) ≤ vel_max
    u_min ≤ u(t) ≤ u_max

    # initial conditions
    pos(t0) == pos_t0
    vel(t0) == vel_t0

    # final conditions
    pos(tf) == pos_tf
    vel(tf) ≥ vel_tf_min

    # dynamics
    ẋ(t) == [vel(t), a * u(t) - b * cos(c * pos(t))]

    # objective
    tf → min
end

JuMP ​

valid

A JuMP model, already discretized: the scheme and the grid are chosen when the problem is built. Load JuMP and Ipopt.

Get and solve ​

julia
using JuMP, Ipopt, OptimalControlProblems

nlp = mountain_car(
    JuMPBackend();
    grid_size=200,
    scheme=:trapeze,
)
set_optimizer(nlp, Ipopt.Optimizer)
optimize!(nlp)
objective_value(nlp)

The model ​

The model as written in ext/JuMPModels/mountain_car.jl, where the parameters are read from the metadata.

julia
data = ProblemData(;
    state=[
        Component("pos"; lower=pos_min, upper=pos_max),
        Component("vel"; lower=vel_min, upper=vel_max),
    ],
    control=[Component("u"; lower=u_min, upper=u_max)],
    variable=[Component("tf"; lower=tf_min)],
    costate=["∂pos", "∂vel"],
    times=v -> (t0, v[1]),
    dynamics=(x, u, v, t) -> [x[2], a * u[1] - b * cos(c * x[1])],
    cost=(I, x0, xf, v) -> v[1],
    boundary=[
        (pos_t0, (x0, xf, v) -> x0[1], pos_t0),
        (vel_t0, (x0, xf, v) -> x0[2], vel_t0),
        (pos_tf, (x0, xf, v) -> xf[1], pos_tf),
        (vel_tf_min, (x0, xf, v) -> xf[2], Inf),
    ],
)

Comparison of the modelings ​

Same problem ​

Two modelings of the same problem, discretized the same way, must give the same nonlinear program: same variables, constraints, objective and derivatives at the initial guess. This is what is compared, not the solutions: two solves are two optimization paths.

  • OptimalControl, scalarized and OptimalControl: same NLP, checked on every pull request.

  • JuMP and OptimalControl: same NLP, checked on every pull request.
