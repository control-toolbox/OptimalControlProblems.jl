SAME_SOLUTION [Constant] ​

OptimalControlProblems.SAME_SOLUTION Constant

Relative gap below which two objectives are the same solution (#378): above the accuracy of the solvers at the tolerance of the tests (about 1e-6 at tol = 1e-8), below the gap between the known local solutions (1.6e-4 on mountain_car). Used to group the solutions reached, to say whether the configurations agree, and to say which solution a solve reached.

features [Function] ​

OptimalControlProblems.features Function
julia
features(
    problem::Symbol
) -> NamedTuple{(:state_dimension, :control_dimension, :variable_dimension, :cost, :initial_time, :final_time, :constraints), <:Tuple{Any, Any, Any, Symbol, Symbol, Symbol, @NamedTuple{state_box::Int64, control_box::Int64, variable_box::Int64, path::Int64, boundary::Int64}}}

Features of problem, computed from its OptimalControl model, never written by hand:

  • state_dimension, control_dimension, variable_dimension;

  • cost: :mayer, :lagrange or :bolza;

  • initial_time, final_time: :fixed or :free;

  • constraints: the number of constraints of each kind, state_box, control_box, variable_box (box constraints), path (nonlinear path constraints) and boundary (nonlinear boundary constraints).

The problem is built with its default parameters, which needs the OptimalControlModels extension: load OptimalControl. A problem without an OptimalControl model has no features yet.

Example

julia
julia> using OptimalControl, OptimalControlProblems

julia> OptimalControlProblems.features(:beam).cost
:lagrange

initial_guess_data [Function] ​

OptimalControlProblems.initial_guess_data Function
julia
initial_guess_data(problem::Symbol) -> Any
initial_guess_data(
    problem::Symbol,
    parameters::Union{Nothing, NamedTuple}
) -> Any

Return the initial guess of problem for its default parameters, merged with parameters if given: (state=…, control=…, variable=…), each component a constant, a vector, or a function of the time t.

The initial guess is shared by every modeling (#377): it is a function of the parameters in the metadata of the problem (ext/MetaData/<problem>.jl). The OptimalControl modelings pass it as is; JuMP evaluates it at the nodes of the scheme. Every modeling takes another one with the keyword init when the problem is built.

Example

julia
julia> OptimalControlProblems.initial_guess_data(:beam)
(state = [0.05, 0.1], control = 0.1)

reference_objective [Function] ​

OptimalControlProblems.reference_objective Function
julia
reference_objective(
    problem::Symbol;
    grid_size,
    scheme
) -> Any

Return the reference objective of problem discretized on grid_size steps with scheme, or nothing when the problem has none for this discretization.

The reference objectives are computed from the convergence tests of every modeling and configuration, by tools/references/update.jl: the best objective among the solves that converged. They are stored in problem_metadata(problem)[:reference_objective], with how they were obtained.

Example

julia
julia> OptimalControlProblems.reference_objective(:beam)
8.889...

reference_solution_data [Function] ​

OptimalControlProblems.reference_solution_data Function
julia
reference_solution_data(problem::Symbol) -> Any
reference_solution_data(
    problem::Symbol,
    parameters::Union{Nothing, NamedTuple}
) -> Any

Return the analytic solution of the continuous problem for parameters (merged with the default ones), or nothing when none is known for them: a named tuple with state and control, functions of the time, the objective, and its source.

It is the solution of the continuous problem: the objective of a discretized problem differs from it by the discretization error, which the reference objective includes.

Example

julia
julia> OptimalControlProblems.reference_solution_data(:beam).objective
8.88888888888889

Component [Struct] ​

JuMPModels.Component Type
julia
struct Component

A component of the state, the control or the variable: its name (also the name of the JuMP container) and bounds. A bound is a number, or for the state and the control a vector over the nodes 0:N; nothing leaves it unset. The start values come from the initial guess of the problem (#377), not from the components.

source

ProblemData [Struct] ​

JuMPModels.ProblemData Type
julia
struct ProblemData

The data of an optimal control problem, written once for every scheme.

The functions receive, at one node, the vectors x (state), u (control), v (variable) of JuMP variables and the time t; x0, xf are the state at the first and last nodes.

  • times(v): the initial and final times, numbers or expressions of v.

  • dynamics(x, u, v, t): the vector ẋ.

  • lagrange(x, u, v, t): the integrand of the cost, or nothing.

  • cost(I, x0, xf, v): the objective, given the discretized integral I of the Lagrange cost (0 without one).

  • path: (lower, f, upper) with f(x, u, v, t), imposed at every node.

  • boundary: (lower, f, upper) with f(x0, xf, v).

The control (0-based) used at the node k of a grid of N steps, by the path constraints.
