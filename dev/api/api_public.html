OptimalControlProblems.Catalogue Module

The catalogue: one function per problem (beam, chain, …), whose methods for each modeling are defined by the extensions, the list of the problems available in some modelings with some status (problems), and the status of a problem in each modeling (status).

Depends on Modelings and Metadata.

problems [Function] ​

OptimalControlProblems.Catalogue.problems Function
julia
problems(; status) -> Vector{Symbol}

Returns the sorted list of optimal control problems.

Availability comes from the model files present in ext/<modeling>Models/; the status (:valid or :draft) of each problem in each modeling comes from its metadata.

  • problems(): problems having the requested status in at least one modeling.

  • problems(backend): problems available in that modeling with the requested status.

  • problems(backend1, backend2, ...): problems available in all the given modelings with the requested status, which is the list to use to compare modelings.

Keyword arguments

  • status::Symbol=:valid: :valid, :draft or :all.

Returns

  • Vector{Symbol}: A vector of problem names as symbols.

Example

julia
julia> OptimalControlProblems.problems(JuMPBackend(), OptimalControlBackend())
[:balanced_field, :beam, ...]

From OptimalControlProblems ​

OptimalControlProblems [Module] ​

OptimalControlProblems Module

A collection of optimal control problems, each available in one or more modelings (OptimalControl, its scalarized form, JuMP), loaded by the extensions.

The code is split into submodules (ct-conventions MOD1, MOD2), in dependency order: Modelings, Metadata, References, Catalogue, Problems. The package re-exports their public API, which is the API of the package; what a submodule does not export is reached through it, e.g. OptimalControlProblems.Metadata.METADATA_SCHEMA. See src/README.md.

source

OptimalControlProblems.Metadata [Module] ​

OptimalControlProblems.Metadata Module

The metadata of the problems: the list of the problems (one file per problem in ext/MetaData/), the schema of a metadata file, loading and checking every file, and reading them: problem_metadata, grid_size_data, parameters_data, initial_guess_data. The analytic solutions used by some metadata files (reference_solution) are defined here too.

Depends on no other submodule.

initial_guess_data [Function] ​

OptimalControlProblems.Metadata.initial_guess_data Function
julia
initial_guess_data(problem::Symbol) -> Any
initial_guess_data(
    problem::Symbol,
    parameters::Union{Nothing, NamedTuple}
) -> Any

Return the initial guess of problem for its default parameters, merged with parameters if given: (state=…, control=…, variable=…), each component a constant, a vector, or a function of the time t.

The initial guess is shared by every modeling (#377): it is a function of the parameters in the metadata of the problem (ext/MetaData/<problem>.jl). The OptimalControl modelings pass it as is; JuMP evaluates it at the nodes of the scheme. Every modeling takes another one with the keyword init when the problem is built.

Example

julia
julia> OptimalControlProblems.initial_guess_data(:beam)
(state = [0.05, 0.1], control = 0.1)

source
julia
problem_metadata(
    problem::Symbol
) -> OrderedCollections.OrderedDict

Return a dictionary containing the metadata of problem, without building it.

The metadata of a built problem is read with metadata(pb) on the Problem. The following keys are valid:

  • grid_size::Int: the default number of steps. For example:
julia
:grid_size => 500,
  • parameters::Union{Nothing,NamedTuple}: the list of parameters. For example:
julia
:parameters => (
    t0 = 0,
    tf = 1,
    x₁_l = 0,
    x₁_u = 0.1,
    x₁_t0 = 0,
    x₂_t0 = 1,
    x₁_tf = 0,
    x₂_tf = -1,
),

  • status: the status (:valid or :draft) of the problem in each modeling.

  • init: the initial guess of every modeling, a function of the parameters (see OptimalControlProblems.initial_guess_data).

  • reference_solution (optional): the analytic solution of the continuous problem, a function of the parameters; see OptimalControlProblems.reference_solution_data.

Example

julia
julia> data = problem_metadata(:beam)
julia> data[:grid_size]
500

From OptimalControlProblems.References ​

OptimalControlProblems.References [Module] ​

OptimalControlProblems.References Module

The references of the problems: the reference objectives and the known solutions of each problem, read from ext/MetaData/references/<problem>.toml (generated by tools/references/update.jl), and the analytic solutions of the continuous problems: reference_objective, solution_kind, reference_solution_data, SAME_SOLUTION. Each known solution says how it was obtained, as a NumericalReference; an analytic solution is an AnalyticReference (#409): references, best_reference, analytic_reference, and objective(ref).

Depends on Metadata, whose metadata it completes with the field :reference_objective.

NumericalReference [Struct] ​

OptimalControlProblems.References.NumericalReference Type
julia
struct NumericalReference <: OptimalControlProblems.References.AbstractReference

A known solution of the problem problem discretized on grid_size steps with scheme (#378), and how it was obtained (#409): one of the solves that reached it, chosen to represent it (a strict convergence before an acceptable one, then the smallest constraint violation), with its modeling, modeler, solver and every option of the solver, its exit status, iterations, time and constraint violation, and the environment of its run.

Generated by tools/references/update.jl from the convergence and robustness tests. The trajectories are not kept: the configuration is enough to solve again.

Fields

  • problem::Symbol: Name of the problem.

  • scheme::Symbol: Discretization scheme, e.g. :trapeze.

  • grid_size::Int64: Number of steps of the grid.

  • objective::Float64: Objective of the solve.

  • solves::Int64: Number of solves, every modeling, configuration and platform, that reached the solution.

  • configurations::Vector{String}: The configurations that reached it, "<modeling> <configuration>".

  • modeling::Symbol: Modeling of the solve, e.g. :OptimalControl.

  • configuration::String: Configuration of the solve, as the tests name it.

  • modeler::Union{Nothing, Symbol}: Modeler of the solve (:adnlp, :exa), nothing for JuMP.

  • solver::Symbol: Solver of the solve, e.g. :ipopt.

  • options::NamedTuple: Every option given to the solver, defaults included.

  • status::Symbol: Exit status of the solver, e.g. :first_order, :LOCALLY_SOLVED, :acceptable.

  • iterations::Int64: Number of iterations.

  • time::Float64: Solve time in seconds, on platform.

  • violation::Float64: Largest violation of the constraints, as the modeling measures it.

  • platform::String: Platform of the run, e.g. cron-OptimalControl-1.13-ubuntu-latest.

  • run::String: The run that solved it (a GitHub Actions run), or local.

  • commit::String: Commit of the package.

  • julia::VersionNumber: Julia version.

  • machine::@NamedTuple{os::String, arch::String, cpu::String}: Operating system, architecture and processor of the platform.

  • versions::NamedTuple: Versions of the packages that modeled, discretized and solved it.

source

SAME_SOLUTION [Constant] ​

OptimalControlProblems.References.SAME_SOLUTION Constant

Relative gap below which two objectives are the same solution (#378): above the accuracy of the solvers at the tolerance of the tests (about 1e-6 at tol = 1e-8), below the gap between the known local solutions (1.6e-4 on mountain_car). Used to group the solutions reached, to say whether the configurations agree, and to say which solution a solve reached.

Problem [Struct] ​

OptimalControlProblems.Problems.Problem Type
julia
struct Problem{M, I<:NamedTuple}

An optimal control problem of the collection: the continuous model, as written with OptimalControl, and its initial guess. Discretizing and solving it is left to OptimalControl.solve, where the scheme, the grid, the modeler and the solver are chosen.

A Problem is returned by a problem function for the OptimalControl modelings. Read it through model(pb), initial_guess and metadata(pb).

Fields

  • name::Symbol: Name of the problem.

  • modeling::Symbol: Modeling the problem is written in, e.g. :OptimalControl.

  • ocp::Any: Continuous optimal control problem.

  • init::NamedTuple: Initial guess, a NamedTuple (state=…, control=…, variable=…).

  • metadata::OrderedCollections.OrderedDict{Symbol, Any}: Metadata of the problem, with the parameters this instance was built with.

Example

julia
julia> using OptimalControl, OptimalControlProblems
julia> pb = beam(OptimalControlBackend())
julia> sol = solve(model(pb); init=initial_guess(pb), grid_size=500)

Features of problem, computed from its OptimalControl model, never written by hand:

  • state_dimension, control_dimension, variable_dimension;

  • initial_time, final_time: :fixed or :free;

  • constraints: the number of constraints of each kind, state_box, control_box, variable_box (box constraints), path (nonlinear path constraints) and boundary (nonlinear boundary constraints).

The problem is built with its default parameters, which needs the OptimalControlModels extension: load OptimalControl. A problem without an OptimalControl model has no features yet.

Example

julia
julia> using OptimalControl, OptimalControlProblems

julia> OptimalControlProblems.features(:beam).cost
