# Reference objectives

Each problem has a **reference objective** per scheme, at its default grid:
`ext/MetaData/references/<problem>.toml`, one table per scheme, with the **known solutions**
of the problem (#378). These files are generated by `update.jl` from the results of the
convergence and robustness tests. Never edit them by hand.

The package reads them into the metadata (`problem_metadata(p)[:reference_objective]`), and
`OptimalControlProblems.reference_objective(p; grid_size, scheme)` returns the value for one
discretization, or `nothing`. `OptimalControlProblems.solution_kind(p, objective; grid_size,
scheme)` says which known solution an objective is: `:best`, `:local` or `:new`. The
convergence and robustness reports (`test/README.md`) show both for each solve.

## What a reference is

- **Value:** the best objective among the solves that converged, over every modeling,
  configuration and platform of the convergence and robustness tests, at the default grid.
  Every problem of the collection is a minimization.
- **`solutions`:** the distinct solutions reached, best first, each with its objective, its
  number of solves and the configurations that reached it. Two objectives within a relative
  `OptimalControlProblems.SAME_SOLUTION` (1e-5) are the same solution. 1e-5 is above the
  accuracy of the solvers at `tol = 1e-8` (about 1e-6), and below the gap between the two
  known solutions of `mountain_car` (1.6e-4).
- **`agreement`:** `true` when every solve reached the same solution.
- **`spread`:** the relative gap between the best and the worst objective.
- **`grid_size`, `parameters`:** the default grid and parameters of the problem when the
  reference was computed. If either changes, the consistency tests fail. Compute the
  reference again.
- **`run`:** where the results come from (a cron run, or `local`). The package versions are
  in the logs of that run.

## Computing the references

From the cron runs: the weekly convergence runs (one per environment: JuMP, OptimalControl,
OptimalControlScalarized) **and** the latest monthly robustness run (`CronRobustness.yml`),
on `main` or on a branch with `workflow_dispatch`. Give all of them together: each file is
recomputed from the results given, and a run left out loses the solutions only it found.

```bash
gh run download <id> --dir results/<id>      # for each run
julia --project=. tools/references/update.jl --run <url of a run> results/*
```

Or locally, after the convergence tests:

```julia
using Pkg
Pkg.test(; test_args=["cron"])                         # every environment, or
Pkg.test(; test_args=["OptimalControl", "cron", "problem=beam"])
```

```bash
julia --project=. tools/references/update.jl test/reports
```

The script writes the problems it has converged results for, and keeps the other schemes of
an existing file. It prints one line per problem and scheme, and flags disagreements. Commit
the files and say in the pull request where the results come from.

## When to compute them again

- A problem's default grid or parameters change: the consistency tests say which ones.
- The cron report shows an objective change that you accept, for example a better local
  solution reached with a new initial guess.
- A new problem, or a new scheme in the convergence tests (#284).
